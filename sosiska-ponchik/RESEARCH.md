# Research: Sausage Runner — Web Runner Game

## Тип проекта
website (browser game, single HTML file)

## Описание идеи
Браузерная веб-игра в жанре endless runner. Главный герой — сосиска, которая бежит по дорожке, разделённой на 3 линии. Игрок переключает линии стрелками влево/вправо. На пути появляются пончики: нужно вовремя прыгнуть и пролететь сквозь дырку пончика. При попадании в дырку — очки, при промахе — теряется жизнь. Всего 3 жизни. Скорость постепенно растёт. Есть бустеры, улучшающие геймплей.

Уникальная механика: сосиска бежит вертикально (стоя), а при прыжке сквозь пончик анимационно переворачивается горизонтально и пролетает через отверстие.

## Рекомендуемый стек

- **Frontend/Engine:** Vanilla HTML5 Canvas API (без фреймворков)
- **Язык:** JavaScript ES6+ (встроен в HTML-файл)
- **Рендеринг:** 2D Canvas Context (`requestAnimationFrame` game loop)
- **Физика:** Ручная реализация — гравитация, линейная интерполяция (lerp) для плавного переключения линий
- **Звук:** Web Audio API (встроен в браузер)
- **Хранение:** localStorage для рекорда (high score)
- **Сборка:** Отсутствует — один `.html` файл, открывается в браузере напрямую
- **Дополнительно:** Canvas drawImage для спрайтов, requestAnimationFrame + deltaTime для консистентной скорости

## Обоснование выбора стека

Vanilla HTML5 Canvas выбран по следующим причинам:
1. **Нет зависимостей** — один файл, открывается в любом браузере без сервера, npm или сборки.
2. **Полный контроль** — механика прыжка сквозь пончик с переворотом (вертикальный → горизонтальный) требует кастомной анимации, которую удобнее писать напрямую через Canvas 2D transforms (`ctx.save/restore`, `ctx.rotate`).
3. **Производительность** — для 2D раннера с несколькими объектами на экране Canvas более чем достаточен. Phaser.js добавил бы 1+ МБ зависимости без реальной необходимости.
4. **Простота отладки** — весь код в одном месте, нет слоёв абстракции.
5. **Доказанный подход** — Canabalt, многие jam-игры успешно реализованы именно так.

## Ключевые функции для MVP

1. **3-линейная дорожка** — три чёткие вертикальные полосы, сосиска переключается между ними клавишами ArrowLeft/ArrowRight с lerp-анимацией (плавный слайд за ~150мс).
2. **Прыжок сквозь пончик** — основная механика: пончики едут навстречу, игрок нажимает ArrowUp или Space для прыжка. Во время прыжка сосиска анимируется из вертикального положения в горизонтальное (поворот 90°) и пролетает сквозь отверстие. Попадание в отверстие = +очки, столкновение с телом пончика = -1 жизнь.
3. **Система жизней** — 3 жизни, отображаемые значками (мини-сосисок или сердечек) в HUD. При потере жизни — экран моргает красным (screen flash).
4. **Нарастающая скорость** — базовая скорость ~200px/s, каждые 10 очков или каждые 20 секунд скорость увеличивается на 5%, до максимума ~500px/s.
5. **Система очков** — +10 за каждый пончик. Счёт в реальном времени отображается в HUD. Рекорд сохраняется в localStorage.
6. **Бустеры** — минимум 2-3 на MVP (см. ниже), появляются как коллектибл-объекты на дорожке.
7. **Game Over экран** — итоговый счёт, рекорд, кнопка "Играть снова".

## Бустеры и дополнительные механики

### Бустеры (подбираемые во время бега):

| Бустер | Иконка | Эффект | Длительность |
|--------|--------|--------|--------------|
| Щит (Shield) | Звёздочка | Один промах не засчитывается, жизнь не теряется | Одноразовый |
| Двойные очки (x2) | Монета с x2 | Каждый пончик даёт 20 очков вместо 10 | 10 сек |
| Замедление (Slow-Mo) | Часы | Пончики летят в 2x медленнее, легче прыгнуть | 8 сек |
| Магнит (Magnet) | Магнит | Автоматически переключает на нужную линию к ближайшему пончику | 5 сек |
| Мини-сосиска (Mini) | Маленькая сосиска | Сосиска уменьшается, отверстие пончика "увеличивается" относительно — проще попасть | 10 сек |

### Дополнительные фишки (сверх MVP):

- **Комбо-система**: если подряд попасть в 3+ пончика без промаха — комбо-множитель x1.5, x2 и т.д. Комбо сбрасывается при промахе.
- **Разные типы пончиков**: обычный (стандартное отверстие), маленький пончик (меньше отверстие, +20 очков), гигантский пончик (большое отверстие, +5 очков — "подарок").
- **Анимация персонажа**: покачивание при беге (bobbing), растяжение/сжатие (squash & stretch) при прыжке — классика game juice.
- **Частицы**: конфетти при попадании сквозь пончик, красная вспышка при промахе.
- **Screen shake**: лёгкое дрожание экрана при потере жизни.
- **Фоновый параллакс**: 2-3 слоя фона с разной скоростью для ощущения глубины.

## Технические детали реализации

### Переключение линий (Smooth Lane Switch):
```javascript
// Позиции линий по X
const LANES = [150, 300, 450];
let currentLane = 1;
let playerX = LANES[1];
let targetX = LANES[1];

// Плавное движение через lerp
playerX += (targetX - playerX) * 0.18; // ~150ms при 60fps
```

### Прыжок и анимация переворота:
```javascript
// Прыжок
if (isJumping) {
  velocityY -= GRAVITY * deltaTime;
  playerY += velocityY * deltaTime;

  // Поворот сосиски горизонтально в пике прыжка
  const jumpProgress = (playerY - groundY) / jumpHeight; // 0..1
  const rotation = jumpProgress * Math.PI / 2; // 0 → 90 degrees
  ctx.save();
  ctx.translate(playerX, playerY);
  ctx.rotate(rotation);
  drawSausage(ctx);
  ctx.restore();
}
```

### Детекция попадания в дырку пончика:
Пончик — кольцо с внешним радиусом R и внутренним r (отверстие).
- Попадание в дырку: расстояние от центра пончика до центра сосиски < r → SUCCESS (+очки)
- Попадание в тело: расстояние >= r AND <= R → MISS (-жизнь)
- Если сосиска на той же линии и пропустила пончик (пончик ушёл за экран без прыжка) → MISS (-жизнь)

### Game Loop с deltaTime:
```javascript
let lastTime = 0;
function gameLoop(timestamp) {
  const deltaTime = (timestamp - lastTime) / 1000; // секунды
  lastTime = timestamp;

  update(deltaTime);
  draw();
  requestAnimationFrame(gameLoop);
}
```

## Риски и сложности

- **Детекция попадания в кольцо** — самая сложная часть. Нужно различить: (1) сосиска в отверстии, (2) сосиска в теле пончика, (3) сосиска не прыгнула и пончик прошёл мимо. Решение: hitbox-зоны для внутреннего и внешнего радиуса пончика + флаг "прошёл ли пончик через игрока".
- **Анимация переворота** — поворот сосиски из вертикали в горизонталь должен происходить именно в момент прохождения сквозь пончик, а не просто при прыжке. Требует синхронизации позиции игрока с позицией пончика по X.
- **Баланс сложности** — скорость роста должна быть ощутимой, но не слишком агрессивной. Рекомендуется нелинейный рост: быстрый прирост в начале, замедление после определённого порога.
- **Производительность на мобильных** — Canvas 2D быстр, но анимации частиц + параллакс нужно ограничивать по количеству. Рекомендуется пул объектов (object pooling) для пончиков и частиц.
- **Управление на мобильных** — стрелки на клавиатуре не работают на смартфонах. Дополнительно: touch-свайпы (swipe left/right/up).

## Доработка: Конвертация игры в 3D

### Что исследовано

#### 1. Выбор библиотеки: Three.js vs Babylon.js

| Критерий | Three.js | Babylon.js |
|----------|----------|------------|
| Размер (minified+gzip) | **168 kB** | 1.4 MB |
| CDN / single HTML | **Отлично** — importmap + jsDelivr | Работает, но тяжело |
| Сложность для простой игры | **Низкая** — только нужные примитивы | Высокая — избыточные фичи |
| 3D runner примеры | **Много** (Tutsplus, Medium, GitHub) | Мало |
| Производительность (idle FPS) | ~56 FPS | ~60 FPS |
| Еженедельные загрузки npm | **5 млн** | ~16 тыс. |
| Встроенная физика | Нет (ручная) | Есть (не нужна для раннера) |

**Вывод: Three.js** — оптимальный выбор. Babylon.js избыточен: в 8x тяжелее, а встроенная физика и редактор для этой задачи не нужны.

#### 2. CDN-подключение в single HTML файле

Актуальный способ (Three.js r175+) — ES modules через importmap:

```html
<script type="importmap">
{
  "imports": {
    "three": "https://cdn.jsdelivr.net/npm/three@0.175.0/build/three.module.js",
    "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.175.0/examples/jsm/"
  }
}
</script>
<script type="module">
  import * as THREE from 'three';
  // весь игровой код здесь
</script>
```

Поддержка importmap: ~85% браузеров (все современные). Работает без сервера, npm, сборки.

#### 3. Архитектура 3D runner: камера и перспектива "за персонажем"

Доказанный паттерн из реальных Three.js раннеров:

```javascript
// Камера позади и выше персонажа
const camera = new THREE.PerspectiveCamera(60, W/H, 0.1, 1000);
// Позиция: смещение (0, +5, -10) относительно игрока
// В update loop:
camera.position.set(player.position.x, player.position.y + 5, player.position.z - 10);
camera.lookAt(player.position.x, player.position.y + 1, player.position.z + 5);
```

**Движение мира, а не персонажа** — ключевой приём для endless runner:
- Персонаж стоит у начала координат (z = 0)
- Препятствия движутся по -Z к камере (`obstacle.position.z += speed * dt`)
- Это предотвращает накопление floating-point ошибок при длинных забегах

#### 4. Система 3 линий в 3D

```javascript
// Линии по оси X, движение по оси Z
const LANES_X = [-2.5, 0, 2.5]; // левая, центр, правая
let targetLaneX = LANES_X[1];   // старт — центр

// В update:
player.position.x += (targetLaneX - player.position.x) * 0.15; // lerp
```

Дорожка: три PlaneGeometry-полосы или одна широкая плоскость с разметкой.

#### 5. Геометрия объектов

| Объект | Three.js геометрия | Параметры |
|--------|-------------------|-----------|
| Сосиска | `CylinderGeometry` | radiusTop=0.3, radiusBottom=0.35, height=1.2, radialSegments=12 |
| Пончик | `TorusGeometry` | radius=1.2, tube=0.45, radialSegments=16, tubularSegments=24 |
| Дорожка | `PlaneGeometry` | width=8, height=200, повернуть на -90° по X |
| Бустеры | `SphereGeometry` / `BoxGeometry` | radius=0.4 |

Для сосиски добавить `MeshPhongMaterial` с коричнево-розовым цветом + `HemisphereLight` + `DirectionalLight`.

#### 6. Производительность: сколько объектов при 60fps

- Менее 100 draw calls — стабильные 60fps на любом устройстве
- Для раннера на экране одновременно 5-8 пончиков + 3-5 бустеров = ~15 объектов, что совершенно безопасно
- Использовать object pooling (recycling) для пончиков: не удалять/создавать, а переиспользовать
- Сегментность геометрий: `radialSegments=12` для цилиндра и `radialSegments=16` для тора — достаточно красиво, не тяжело

#### 7. Коллизии в 3D

Заменить 2D-кольцевую проверку на 3D `Box3` (AABB):
```javascript
const playerBox = new THREE.Box3().setFromObject(player);
const donutBox  = new THREE.Box3().setFromObject(donut);
const holeBox   = new THREE.Box3().setFromObject(donut.holeHelper); // невидимый helper внутри тора

if (playerBox.intersectsBox(holeBox)) {
  // SUCCESS — попал в дырку
} else if (playerBox.intersectsBox(donutBox)) {
  // MISS — врезался в тело пончика
}
```

### Рекомендации по стеку

**Новая зависимость:** Three.js v0.175.0 via jsDelivr CDN (importmap)

```
Three.js r175
├── THREE.WebGLRenderer    — рендерер
├── THREE.PerspectiveCamera — камера за персонажем (FOV 60, offset: y+5 z-10)
├── THREE.Scene            — сцена
├── THREE.CylinderGeometry — сосиска
├── THREE.TorusGeometry    — пончик
├── THREE.PlaneGeometry    — дорожка (повёрнута -90° X)
├── THREE.MeshPhongMaterial — материалы с освещением
├── THREE.HemisphereLight   — ambient освещение
├── THREE.DirectionalLight  — направленный свет (тени)
└── THREE.Box3             — коллизии (AABB)
```

**Что НЕ меняется:**
- Структура файла — по-прежнему один `.html`
- Игровая логика — скорость, очки, жизни, бустеры, lerp переключения линий
- localStorage для рекорда
- HUD — рисуется поверх canvas через 2D overlay (div с position:absolute)

**Что меняется:**
- Рендеринг: Canvas 2D ctx → Three.js WebGLRenderer
- Координаты: 2D (px) → 3D units (X=линии, Y=высота прыжка, Z=движение мира)
- Рисование объектов: ctx.arc/fillRect → THREE.Mesh с геометрией и материалом
- Камера: фиксированная → следящая за игроком (behind-camera)

**Риски доработки:**
- Hitbox тора (TorusGeometry) сложнее, чем кольцо в 2D — рекомендуется невидимый inner BoxGeometry как helper для определения "дырки"
- Переориентация осей: в 2D Y растёт вниз, в 3D Y растёт вверх, Z — глубина (в камеру)
- Тени могут снизить FPS на мобильных — использовать `castShadow=false` или упрощённые тени
