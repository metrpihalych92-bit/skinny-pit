# DEVLOG — Sausage Runner 3D

## Pipeline #8 — Доработка до 3D

### Задача
Конвертировать 2D Canvas-игру в 3D версию с использованием Three.js.

### Реализация (Developer агент)

**Стек:**
- Three.js r160 (ES module через importmap + jsDelivr CDN)
- THREE.WebGLRenderer, PerspectiveCamera FOV 65
- HUD — HTML div overlay поверх canvas
- Звук — Web Audio API (без изменений)

**Архитектурные решения:**
- Один файл `index.html` — без сборки
- Координатная система: X (линии -2.5/0/2.5), Y (высота прыжка), Z (движение объектов)
- Дорожка и здания статичны, движутся через `position.z` смещение (world scrolling)
- Сосиска стоит на месте (z=0), пончики летят навстречу по Z
- Камера следует за игроком: lerp по X, фиксированная высота, lookAt впереди игрока

**Объекты:**
- Сосиска: CylinderGeometry + caps + eyes + smile group, squash & stretch анимация
- Пончик: TorusGeometry, hole-зона по holeR = (radius - tube) * 0.88
- Бустер: SphereGeometry + PointLight glow, 5 типов
- Частицы: отдельные SphereGeometry meshes с gravity и opacity fade
- Здания: BoxGeometry pool (32 штуки), переиспользуются при выходе за экран

**Коллизия пончика:**
- inWin окно: z от -1.2 до +2.8 (доступная зона вокруг игрока)
- Успех: dy < holeR && !player.onGround (прыгает через дырку)
- Промах: dz <= -1.2 && same lane && !inv (пончик прошёл мимо)

## Проверка кода (Reviewer агент) — 2026-03-30

### Найденные проблемы

**P4 (исправлено): Утечка памяти — Player.dispose()**
- Метод `dispose()` вызывал только `this._mat.dispose()` — материал тела сосиски.
- Не освобождались: геометрии тела/cap/глаз/улыбки, материалы глаз и улыбки, геометрия/материал щита.
- При каждом рестарте игры все эти объекты накапливались в GPU-памяти.
- Исправлено: заменено на `this.mesh.traverse(obj => { if (obj.isMesh) { obj.geometry.dispose(); obj.material.dispose(); } })`.

**P5 (исправлено): Утечка памяти — Donut3D.dispose()**
- Метод `dispose()` освобождал только геометрию и материал основного mesh (тора).
- Не освобождались геометрия и материал каждого из 5-9 спринклов (BoxGeometry + MeshBasicMaterial), добавленных как дочерние объекты.
- При обычной игре на экране может быть до 10 пончиков одновременно, каждый с 5-9 утечками геометрий.
- Исправлено: аналогично P4, через `traverse`.

**P6 (исправлено): Frame-rate зависимость камеры**
- `updateCamera()` использовал `lerp(x, target, 0.09)` — значение `0.09` не учитывает deltaTime.
- При 30fps камера отставала от игрока вдвое сильнее, чем при 60fps.
- Исправлено: заменено на `lerp(x, target, 1 - Math.pow(0.01, dt * 5))` — frame-rate independent lerp.
- `updateCamera` теперь принимает `dt` как параметр; вызов в game loop обновлён: `updateCamera(dt)`.

### Проверка игровой логики (повторная)

- Коллизии пончика: логика без изменений, работает корректно
- Бустеры: Booster3D.dispose() корректен (mesh-сфера + PointLight; PointLight не требует dispose())
- Скролл зданий и частицы: без изменений, работают корректно
- Звук, HUD, localStorage: без изменений
